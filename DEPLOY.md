# Deploying PitchPro to Render

PitchPro is a 3-piece app:
- **Backend** — FastAPI (Python) web service
- **Frontend** — React static site
- **Database** — MongoDB (use MongoDB Atlas free tier — Render doesn't host Mongo)

A `render.yaml` blueprint at the repo root wires up both services in one go.

---

## 0. Prerequisites
- A GitHub account with this repo pushed (use Emergent's "Save to GitHub" button).
- A free [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register) account.
- A free [Render](https://render.com) account.

---

## 1. Spin up MongoDB Atlas (free M0 tier)

1. Sign in to Atlas → **Build a Database** → **M0 Free** → pick a region close to your Render region.
2. **Database Access** → add a database user (note the password).
3. **Network Access** → **Add IP Address** → *Allow access from anywhere* (`0.0.0.0/0`). Render's IPs are dynamic on the free tier.
4. **Connect** → **Drivers** → copy the `mongodb+srv://...` connection string. Replace `<password>` with the one you set.
5. Append the database name path if you want, e.g. `…mongodb.net/pitchpro?retryWrites=true&w=majority`.

Keep that connection string handy — you'll paste it into Render in step 3.

---

## 2. Deploy with the Render Blueprint

1. Render dashboard → **New** → **Blueprint**.
2. Connect your GitHub account if you haven't, then pick the repo holding this code.
3. Render reads `render.yaml` and shows two services it will create:
   - `pitchpro-backend` (Python web service)
   - `pitchpro-frontend` (Static site)
4. Click **Apply**. Render starts building both. The backend will fail the first build because `MONGO_URL` and `CORS_ORIGINS` aren't set yet — that's fine, fix in step 3.

---

## 3. Set environment variables

### Backend (`pitchpro-backend` service → Environment tab)

| Key | Value |
|---|---|
| `MONGO_URL` | The Atlas `mongodb+srv://…` connection string from step 1.4 |
| `DB_NAME` | `pitchpro` (already defaulted in `render.yaml`) |
| `JWT_SECRET` | Auto-generated by Render — leave as is |
| `CORS_ORIGINS` | Set this **after** the frontend URL is known (step 4). Comma-separated, no trailing slash. |
| `ADMIN_EMAIL` | `admin@cricketacademy.com` (or your own) |
| `ADMIN_PASSWORD` | Strong password for the seeded platform admin |

Click **Save Changes** → Render redeploys the backend. Wait until the service is **Live** and copy its public URL, e.g. `https://pitchpro-backend.onrender.com`.

### Frontend (`pitchpro-frontend` service → Environment tab)

| Key | Value |
|---|---|
| `REACT_APP_BACKEND_URL` | The backend URL from above. **No trailing slash. No `/api` suffix.** |

Click **Save, Rebuild & Redeploy**. The frontend bakes this URL into the build, so any change requires a rebuild.

---

## 4. Wire CORS

After the frontend goes live, copy its URL (e.g. `https://pitchpro-frontend.onrender.com`).

Go back to the backend service → Environment → set:

```
CORS_ORIGINS=https://pitchpro-frontend.onrender.com
```

Save Changes → backend redeploys.

> **Why this matters:** PitchPro uses HTTP-only cookies for auth (`SameSite=None`, `Secure`). Browsers refuse cross-origin credentialed requests when the backend uses a wildcard `*` for `Access-Control-Allow-Origin`. CORS_ORIGINS must list the exact frontend origin.

---

## 5. First-run seeding

On first boot the backend seeds:
- 3 demo academies (Pyare Mohan, Boundary Line, Stumps & Co.)
- A platform admin (`ADMIN_EMAIL` / `ADMIN_PASSWORD`)
- One academy_admin per academy (`hello@<slug>.in / AcaAdmin@1`)
- Demo parent (`user@cricketacademy.com / User@12345`) and coach
- Lanes, coaches, bookings, fees and progress reports for the Pyare Mohan demo academy

If you want to skip the demo data on a clean install, comment out the calls inside the `on_startup` handler in `backend/server.py` before pushing.

---

## 6. Custom domain (optional)

Both services can attach custom domains under their **Settings → Custom Domain** tab. Render handles HTTPS automatically. Don't forget to update `CORS_ORIGINS` and `REACT_APP_BACKEND_URL` to the new hostnames and rebuild.

---

## 7. Free-tier caveats

- **Backend sleeps after 15 minutes** of inactivity. The first request after a sleep takes ~30 s while the dyno spins up. Fine for demos, painful for live users.
- **Atlas free M0** caps out at 512 MB and shared CPU.
- **Static site builds** count against Render's monthly build minutes.

For zero-cold-start production, upgrade the backend to Starter ($7/mo) and Atlas to M2.

---

## 8. Rolling updates

Every push to your default branch triggers automatic redeploys for both services. Open the Render dashboard → service → **Logs** to follow build/runtime output.

If anything looks off, the most common gotchas:
1. `REACT_APP_BACKEND_URL` includes a trailing slash or `/api` → API calls 404.
2. `CORS_ORIGINS` doesn't list the live frontend URL → browser silently drops requests.
3. Mongo Atlas IP allow-list missing `0.0.0.0/0` → backend logs `ServerSelectionTimeoutError`.
4. Free backend just woke up → first request takes ~30 s (this is by design on the free plan).
